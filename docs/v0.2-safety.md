# v0.2 safety model

Server mutation is isolated to `internal/imapx/mutate.go` and can only be called by `internal/policy`. Static AST tests enforce both boundaries. A QQ dialect transcript test executes the conservative copy flow and fails if any command containing `EXPUNGE` is sent.

`QQMAIL_CLI_READONLY=1` blocks every command classified as `mutate`, `destructive`, or `send` before credentials are read or a network connection is opened. `agent-info` reports the current state and each command's risk level.

`clean --execute` requires, in order:

1. A manifest whose HMAC is valid and whose referenced `.eml` SHA-256 hashes all match.
2. Per-message server truth: matching folder UIDVALIDITY, RFC822.SIZE, and Message-ID.
3. With `--paranoid`, a full BODY.PEEK refetch whose SHA-256 matches the backup.
4. A real TTY where the human types the exact eligible message count.

Any gate failure rejects the entire batch. When MOVE is unavailable, the current S5-pending conservative path copies, confirms the destination via COPYUID or Message-ID plus size, and marks only the source UID `\\Deleted`. It intentionally does not remove the source record physically. No user-facing permanent-delete command exists.

Every attempted server mutation is recorded both in SQLite and in an append-only JSONL. `cache clear --execute` removes the full DB/WAL/SHM set and then records its own completion in the independent JSONL, so clearing the cache does not erase the fact that it occurred.
